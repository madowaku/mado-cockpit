# MCC-M2.9 ARTEMIS Mobile Dogfood / Autonomous Android QA Bridge

## Scope
Additive, opt-in Python module `mado_cockpit.artemis_mobile_qa`. No changes to
existing MCC tasks, EvidenceManager, gates or MGSF capture schemas. No app
installation, API calls, or emulator startup is attempted by CI.

## Windows host dogfood
1. Install Android SDK / Android Studio and create a **dedicated disposable emulator**.
2. Clone [google/artemis](https://github.com/google/artemis) at a reviewed/pinned
   revision and follow its official Windows README (`.\\start.bat`).
   The upstream bootstrap can install dependencies and offer global MCP/rules
   changes. Review these prompts and do not automatically install globally.
3. Start the emulator, run `adb devices -l`; use
   `python -c "from mado_cockpit.artemis_mobile_qa import android_doctor; print(android_doctor())"`.
   Only a ready `emulator-...` qualifies for the live gate.
4. Generate a *review-only* Codex MCP snippet:
   `python -c "from mado_cockpit.artemis_mobile_qa import codex_mcp_config; print(codex_mcp_config('C:/work/artemis'))"`.
   Paste into the user's Codex config only after reviewing the actual upstream
   checkout and its dependencies. The snippet runs the upstream `mcp_server`.
5. Use ARTEMIS Pro to exercise a disposable test app with non-production data.
   Record a trace ID, step results and screenshots. Export a JSON manifest
   using the contract below. **The manifest is supplied by an external trusted
   runner, not automatically generated by the upstream MCP server.**
6. Import via `intake_mobile_evidence(session_dir, output_dir)`; retain the
   resulting report and hashed media alongside normal MCC EvidenceManager
   artifacts. A downstream worker may translate this report into MGSF's
   `capture.json` and `timeline.jsonl`, but this module deliberately does
   not claim to implement the full MGSF gameplay schema.

## Input contract (`manifest.json`)
```json
{
  "schema_version": 1,
  "run_id": "demo-android-001",
  "device_serial": "emulator-5554",
  "source": "artemis_live",
  "status": "passed",
  "trace_id": "upstream-trace-id",
  "steps": [{"action": "open test app", "result": "passed"}],
  "media": [{"path": "screenshots/final.png", "kind": "screenshot"}]
}
```
Relative paths only. Screenshot/video files must be present and nonempty;
filenames may not escape the session directory. Reports include SHA-256,
source classification and a pass/fail/blocked gate. Media is copied without
modifying source assets. Treat copied evidence as potentially sensitive; use
isolated devices and do not upload personal data.

## Quality gates
- **Offline CI**: tests run without ADB, Artemis or paid API credentials.
- **Live pass** requires `source=artemis_live`, an emulator serial,
  successful producer status, all steps passing, a trace ID and media.
- **Blocked**: synthetic fixture, no emulator, unavailable ADB, or producer
  blocked status. Fixtures are never promoted to live evidence.
- **Human checkpoint**: approve device permissions, app test accounts and
  external actions before running autonomous interactions.
- **Known limit**: A manifest is declarative; this v0 bridge does not
  cryptographically attest the ARTEMIS runner or prove frames are real images.
  Trusted runner validation and an actual Windows E2E are required before a
  production-quality claim.

## Compatibility
MCC EvidenceManager already owns its own evidence bundles; this bridge creates
a distinct `mobile-qa-report.json` export for later ingestion. MGSF recognizes
`recorded_gameplay_capture` and `synthetic_capture_fixture`, which are
reported as explicit source labels. Actual MGSF capture format conversion is a
separate follow-up and is not silently assumed.
